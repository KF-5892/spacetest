## 1. 背景と目的

### 1.1 背景

ディズニーランドの「スターツアーズ」のように、**誰でも・安全に・数分で「宇宙を飛び回る」非日常体験**ができるアプリを作りたい。
実際のアトラクションはモーションシミュレータ(6自由度油圧筐体)と映像の同期で体感を作っているが、
本プロジェクトはそれを**個人のデバイス(ブラウザ)上の視覚・聴覚・演出設計**で再構成する。

### 1.2 目的

- ユーザーが「宇宙旅行に行ってきた」と感じられる、約5分間の没入型フライト体験を提供する。
- スターツアーズの本質である**「乗客としての気楽さ × ハプニングのスリル × 乗るたびに違う旅」**をデジタルで再現する。
- 実在の太陽系をベースにすることで、エンタメと同時に**宇宙への興味・学び**を喚起する。

### 1.3 本書のゴール

開発着手(PoC/MVP)に必要な、コンセプト・スコープ・機能/非機能要件・技術方針・ロードマップを合意すること。

## 2. コンセプト

### 2.1 コンセプトステートメント

> **「ブラウザを開いて30秒後、あなたは宇宙船の乗客になる。」**
> 予約も操縦免許もいらない、5分間の宇宙遊覧ツアー。
> ただし——このツアー、いつも予定どおりには終わらない。

### 2.2 体験の3本柱

| 柱 | 内容 | 由来 |
|---|---|---|
| ① ライドである | 操縦できなくても楽しい。ガイドに導かれるレール型シネマティック体験 | EX-01, EX-05 |
| ② 生きた宇宙である | 実在の太陽系。惑星は巨大で、星雲は美しく、知識が驚きに変わる | EX-04, EX-10 |
| ③ 二度と同じ旅はない | 出発・航路イベント・目的地の組み合わせで毎回違うツアーになる | EX-06, EX-07 |

### 2.3 スターツアーズから継承する設計原則(→翻訳)

| スターツアーズの原則 | 本アプリでの翻訳 |
|---|---|
| 乗客は操縦しない | ツアーモードは全自動。ただし視点と「ちょい避け」の自由は与える(EX-11) |
| モーションと映像の同期 | モーション筐体の代替として、カメラワーク・FOV変化・画面振動・ゲームパッド/スマホ振動・音圧で体感を作る |
| ハプニングが旅を物語にする | 航路イベント(小惑星帯、デブリ警報、彗星遭遇など)をランダム挿入 |
| 乗るたびに違う(54〜100通り以上) | シーンモジュールのデータ駆動組み合わせ(MVP: 6通り → 拡張で数十通り) |
| 待ち行列も体験の一部 | 発進前ブリーフィング(搭乗案内・機体点検演出)を短く入れる |

### 2.4 世界観・トーン

- **実在の太陽系 × 近未来の民間宇宙ツアー会社**という設定(完全オリジナル世界観)。
- ビジュアルは「誇張された本物」: 天体の配置・見た目は実データ準拠を基本にしつつ、星の密度・色彩・移動時間は体感優先で演出する(映画的リアリティ)。
- 既存IP(スター・ウォーズ等)の名称・キャラクター・音楽・デザインは**一切使用しない**(§8 NFR-20)。

## 4. スコープ定義

### 4.1 やること(In Scope)

- ブラウザで動作する3D宇宙フライト体験(ツアーモード主軸+フリーフライト副軸)
- 太陽系の主要天体の映像的な再現と解説
- シーン組み合わせによるリプレイ性
- PC/スマホ両対応、酔い対策・アクセシビリティ

### 4.2 やらないこと(Out of Scope)— 明示的除外

| 除外項目 | 理由 |
|---|---|
| 戦闘・シューティング・スコア競争 | 「ツアー体験」に集中。スターツアーズも戦闘ゲームではない |
| リアル軌道力学シミュレーション | Elite Dangerousの反面教師(リアルな距離=退屈)。体感優先 |
| マルチプレイヤー・アカウント・ランキング | MVP範囲外。サーバレス(静的配信)で完結させる |
| 課金・広告 | 当面なし |
| ネイティブアプリ(iOS/Android/PC) | Web優先。将来PWA/WebXRで拡張 |
| 実機モーション筐体連動 | 対象外(将来の展示用途で検討余地はメモに留める) |

## 5. 体験設計

### 5.1 モード構成

| モード | 概要 | フェーズ |
|---|---|---|
| **ツアーモード**(主軸) | 全自動・約5分のガイド付き宇宙遊覧。レール(カメラパス)上をシネマティックに飛行 | MVP |
| **フリーフライト**(副軸) | 太陽系を簡易操作で自由に飛ぶ。天体ワンタップでオートアプローチ | Phase 2 |
| フォトモード | 一時停止してカメラを動かし撮影 | Phase 3 |

### 5.2 ツアーモードのユーザージャーニー(標準尺 約5分30秒)

| 時間 | フェーズ | 体験内容 | 演出のポイント | 由来 |
|---|---|---|---|---|
| T+0:00 | ① 搭乗ブリーフィング | ツアー会社の搭乗案内。行き先ガチャの提示(「本日の航路」) | 世界観への助走。スキップ可 | EX-05 |
| T+0:30 | ② 発進シーケンス | カウントダウン→点火→上昇→大気圏離脱 | 儀式化。音圧と振動、雲を抜ける瞬間の光 | EX-02 |
| T+1:15 | ③ 地球軌道 | 青い地球を見下ろす静寂。ISS遠景 | 「静」の見せ場。BGM転調 | EX-04, EX-08 |
| T+1:45 | ④ ワープ | チャージ→ジャンプ。星が線に伸び光のトンネルへ | 溜め→解放。最大のカタルシス | EX-03 |
| T+2:00 | ⑤ 目的地シーン | 目的地モジュール(月面低空/火星峡谷/土星の環 等)を約90秒遊覧 | 目的地ごとの固有の見せ場+ガイド解説 | EX-04, EX-10 |
| T+3:30 | ⑥ 航路イベント | ランダムのハプニング(小惑星接近!等)。限定操作で回避に"参加" | 予定外のスリル。失敗しても物語は続く | EX-06, EX-11 |
| T+4:30 | ⑦ 帰還ワープ→エピローグ | 帰還ジャンプ→地球再突入の光→着陸 | 余韻。搭乗記念カード表示→「もう一度乗る」 | EX-07 |

### 5.3 シーンモジュールと組み合わせ(スターツアーズ方式)

ツアーは「**出発 × 目的地 × 航路イベント**」のモジュール組み合わせで生成する。データ駆動で後から追加可能にする。

| スロット | MVP収録 | Phase 2追加候補 |
|---|---|---|
| 出発 (1種) | 地球・射場発進 | 軌道ステーション発進、夜側発進 |
| 目的地 (3種) | 月(クレーター低空飛行)、火星(マリネリス峡谷)、土星(環くぐり) | 木星(大赤斑)、エウロパ氷原、彗星ランデブー、オリオン大星雲、ブラックホール遠景 |
| 航路イベント (2種) | 小惑星帯突入、スペースデブリ警報 | 太陽フレア、彗星尾の通過、謎の信号(イースターエッグ) |

- MVP: 1×3×2 = **6通り**。Phase 2で 2×8×5 = 80通り規模へ拡張可能な設計とする。
- 組み合わせはランダム提示だが、ユーザーが目的地を指名することも可能(P1親子の学習用途)。

### 5.4 操作設計(ツアーモード)

「操作ゼロで完走できる。しかし手を出すと気持ちいい」を原則とする。

- **視点**: ドラッグ/スワイプ/ジャイロ(スマホ)でコックピットから自由に見回せる(常時)
- **ちょい避け**: 航路イベント中のみ、左右キー/スワイプで機体を数メートル動かせる(レールからは外れない)
- **スキップ/一時停止**: シーン単位のスキップ、いつでも一時停止

### 5.5 音響設計

- 船外は無音、船内はエンジン音・計器音・無線が満たす(インターステラー方式)— EX-08
- BGMはシーン遷移・ワープと同期(Rez方式)。オリジナル曲または権利クリアな楽曲のみ
- ガイド音声: MVPは**字幕+SE**で成立させ、音声(合成音声または収録)はPhase 2

## 8. 非機能要件(NFR)

### 8.1 パフォーマンス

| ID | 要件 | 目標値 |
|---|---|---|
| NFR-01 | フレームレート | ミッドレンジPC(内蔵GPU含む)で60fps、ミッドレンジスマホで30fps以上 |
| NFR-02 | 初回ロード | 4G回線で操作可能まで5秒以内/初期ダウンロード10MB以下。以降のアセットはワープ中等に遅延読込(FR-46連携) |
| NFR-03 | メモリ | モバイルSafariでクラッシュしない実測上限を守る(目安: GPUテクスチャ512MB以下) |

### 8.2 対応環境

| ID | 要件 |
|---|---|
| NFR-10 | Chrome / Edge / Safari / Firefox の各最新2メジャーバージョン(デスクトップ) |
| NFR-11 | iOS Safari / Android Chrome の最新2メジャーバージョン(縦横両対応、横推奨表示) |
| NFR-12 | WebGL 2.0を必須基盤とし、WebGPU対応環境では自動的に高品質パスを使用(プログレッシブエンハンスメント) |
| NFR-13 | 入力: マウス/キーボード、タッチ、ゲームパッド(Gamepad API)、スマホジャイロ(許可制) |

### 8.3 快適性(酔い対策)— 本アプリの生命線

| ID | 要件 |
|---|---|
| NFR-30 | コックピット等の固定参照枠が周辺視野に常に存在すること(FR-30) |
| NFR-31 | 移動は等速基調。加減速イベント(発進・ワープ)は短時間・予告付き・演出で包む |
| NFR-32 | ロール回転(視界の傾き)は演出上最小限に留め、水平基準を維持する |
| NFR-33 | カメラ揺れ・FOV変化は快適性設定(FR-60)で減衰・無効化できる |
| NFR-34 | OSの「視差効果を減らす」(prefers-reduced-motion)を尊重し、自動でモーション低減モードにする |

### 8.4 アクセシビリティ

| ID | 要件 |
|---|---|
| NFR-40 | 全ての音声情報は字幕で代替可能(FR-62) |
| NFR-41 | 色のみに依存しない警報表現(形状・点滅・音・文言の併用)。コントラスト比WCAG AA目安 |
| NFR-42 | キーボードのみでタイトル→ツアー完走→再搭乗まで到達できる |
| NFR-43 | 光過敏への配慮: 高速フラッシュ(3回/秒超)を使用しない。ワープ演出も輝度変化を制御 |

### 8.5 権利・セキュリティ・品質

| ID | 要件 |
|---|---|
| NFR-20 | 既存IP(スター・ウォーズ/ディズニー等)の名称・キャラクター・音楽・固有デザインを使用しない。参考にするのは体験構造のみ |
| NFR-21 | 天体テクスチャ等はNASA/JPL/USGS等のパブリックドメイン素材またはCC0/自作素材を使用し、出典をクレジット画面に記載 |
| NFR-22 | 個人情報を収集しない。外部送信は(導入する場合の)匿名計測のみとし、プライバシーポリシーを明記 |
| NFR-23 | 静的サイトとして配信可能(サーバサイド不要)。CDN配信を前提とする |
| NFR-24 | TypeScript化、Lint/Format、主要ロジック(シーン組合せ・カメラパス)のユニットテスト、CIでのビルド検証 |

## 9. 技術要件・選定方針

| 項目 | 選定 | 理由 |
|---|---|---|
| プラットフォーム | **Webブラウザ(SPA/静的配信)** | インストール不要=「開いて30秒で宇宙」のコンセプトに直結。受賞級の先行事例で実現可能性は実証済み(調査 §5.1)。本リポジトリで即開発可能 |
| 3Dエンジン | **Three.js**(WebGL2基盤、WebGPUレンダラをプログレッシブ採用) | 実績・情報量・パフォーマンスのバランス。ポイントクラウドで数十万星規模の描画実績あり |
| 言語/ビルド | TypeScript + Vite | 型安全と高速な開発イテレーション |
| UI層 | HTML/CSSオーバーレイ(MVPはフレームワークなし、必要になればReact導入を再判断) | HUD・字幕・メニュー程度なら素のDOMで十分軽い |
| カメラパス | Catmull-Romスプライン等によるレール定義+イージング | ツアーモードの根幹。パスデータはJSONで外部化 |
| シーン管理 | **データ駆動のシーンモジュール**(JSON定義: パス・イベント・字幕・BGMキュー) | FR-05の組み合わせ拡張とA/B調整を容易にする |
| アセット方針 | プロシージャル生成(星野・星雲・パーティクル)を主体に、惑星テクスチャはNASA系パブリックドメイン素材 | 初期DL 10MB以下(NFR-02)と権利クリア(NFR-21)の両立 |
| オーディオ | Web Audio API(クロスフェード、簡易ダッキング) | FR-50/51のシーン同期に必要 |
| 将来拡張 | WebXR Device API(VRモード)、PWA、Gamepad/振動API | 調査 §5.2 のVR事例に接続する拡張パス。設計段階でカメラ/入力を抽象化しておく |
| ホスティング | GitHub Pages等の静的ホスティング(検討) | NFR-23 |

**アーキテクチャ原則**: 「シーン=データ、演出=再利用可能なビルディングブロック(ワープ、低空飛行、接近フライバイ…)」に分離し、
シーン追加がコード変更なしで済む状態を目指す(スターツアーズが上映モジュール追加で寿命を延ばしたのと同じ戦略)。

## 10. 開発ロードマップ

| フェーズ | 期間目安 | ゴール | 主な内容 |
|---|---|---|---|
| **Phase 0: PoC** | 1〜2週 | 「気持ちいい」の核の検証 | 星野+レール飛行+ワープ演出1本+コックピット枠。社内/身内レビューで酔い・体感を確認 |
| **Phase 1: MVP** | +4〜6週 | ツアー1本が商品レベルで成立 | 発進→地球軌道→ワープ→目的地3種×イベント2種(6通り)→帰還。HUD・字幕ガイド・BGM/SE・快適性/画質設定・スマホ対応 |

各フェーズ末に**酔いチェックを含むプレイテスト**を実施(NFR-30系の検証)。Phase 0の結果次第で演出パラメータの基準値を確定する。

## 11. リスクと対策

| # | リスク | 影響 | 対策 |
|---|---|---|---|
| R1 | 3D酔いでユーザーが離脱 | 致命的 | 固定参照枠・等速基調を初期設計に組込(後付け不可)。Phase 0から感受性の異なる被験者でテスト |
| R2 | モバイル性能不足(熱・fps低下) | 大 | 画質プリセット+自動判定、プロシージャル軽量アセット、インスタンシング/LOD徹底 |
| R3 | 既存IPとの類似指摘 | 大 | NFR-20の遵守。名称・デザインのオリジナル化、リリース前の第三者チェック |
| R4 | スコープ肥大(フリーフライト沼) | 中 | MoSCoWとフェーズ制で防波堤。MVPはツアーモードのみで成立させる |
| R5 | 音声・音楽素材の品質/権利 | 中 | MVPは字幕+権利クリアBGMで成立させ、音声はPhase 2で合成音声から検証 |
| R6 | 「映像を見てるだけ」と感じられる | 中 | 視点自由(FR-08)とちょい避け(FR-07)で能動性を確保。Phase 0で「操作したくなるか」を検証 |
| R7 | Safari/WebGL実装差異による不具合 | 中 | 対応ブラウザ実機でのスモークテストをCIに準ずる運用で実施 |

## 12. 成功指標(KPI)

| 指標 | 目標 | 意図 |
|---|---|---|
| ツアー完走率 | 70%以上 | 体験が破綻していないこと(離脱=酔い/退屈のシグナル) |
| 再搭乗率(「もう一度乗る」押下) | 30%以上 | ランダム組み合わせの価値検証(EX-07) |
| 平均セッション時間 | 6分以上(1ツアー+α) | 没入の総量 |
| 60fps達成率(PC計測) | 90%以上のセッション | NFR-01の実地検証 |
| 快適性(テスト時アンケート) | 「酔った」報告 5%未満 | R1の監視 |
